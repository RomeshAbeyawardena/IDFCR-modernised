# Security Policy

Thank you for helping keep IDFCR secure. Security is taken seriously, and responsible disclosure is appreciated.

## Supported Versions

Security updates are only provided for the latest stable release.

| Version | Supported |
| ------- | :-------: |
| 3.4.x   | ✅ |
| < 3.4   | ❌ |

Older versions may contain known issues and should be upgraded to the latest supported release.

## Reporting a Vulnerability

If you believe you have discovered a security vulnerability in IDFCR, please report it privately. **Do not create a public GitHub issue**, as this could expose users before a fix is available.

Please include as much information as possible, including:

- A clear description of the vulnerability.
- The affected package(s) and version(s).
- Steps to reproduce the issue.
- A proof of concept, if applicable.
- The potential impact.
- Any suggested mitigation or fix (optional).

### What to expect

- An acknowledgement will normally be provided within **5 working days**.
- Reported vulnerabilities will be investigated and validated.
- If confirmed, a fix will be developed and released as soon as reasonably possible.
- You may be contacted for additional information during the investigation.
- Once a fix is available, a security advisory and release notes will be published where appropriate.

If a report is determined not to be a security vulnerability, an explanation will be provided where possible.

## Scope

This policy applies to all actively supported IDFCR packages and repositories.

Issues relating to application-specific configuration, third-party dependencies, or unsupported versions may fall outside the scope of this policy.

## Responsible Disclosure

Please allow reasonable time for a fix to be developed before publicly disclosing any vulnerability. Coordinated disclosure helps protect users of the framework.
