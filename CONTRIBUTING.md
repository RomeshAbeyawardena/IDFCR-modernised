# Contributing to IDFCR

First of all, thank you for taking the time to contribute!

Whether you're reporting a bug, improving documentation, suggesting an enhancement, or submitting code, your contributions are appreciated.

## Before You Start

Please check existing Issues and Pull Requests before creating a new one to avoid duplicates.

If you're planning a significant feature or architectural change, please open a discussion or issue first so we can agree on the approach before implementation begins.

## Reporting Bugs

When reporting a bug, please include:

- IDFCR version
- .NET version
- Operating system
- A minimal reproducible example
- Expected behaviour
- Actual behaviour
- Any relevant logs or exception details

The easier a problem is to reproduce, the easier it is to fix.

## Suggesting Enhancements

Enhancement proposals are welcome.

When proposing new functionality, please explain:

- The problem being solved
- Why existing functionality is insufficient
- The proposed solution
- Any alternatives considered

Features that reduce boilerplate, improve consistency, or simplify common development patterns are generally preferred.

## Pull Requests

Please keep pull requests focused.

A pull request should ideally address a single issue or feature.

Large pull requests containing unrelated changes are difficult to review and may be declined.

## Coding Guidelines

Please follow the existing coding style throughout the project.

In particular:

- Keep implementations simple and maintainable.
- Prefer consistency over cleverness.
- Avoid unnecessary abstractions.
- Maintain backwards compatibility where practical.
- Add or update documentation when introducing new functionality.
- Include tests where appropriate.

## Architectural Principles

IDFCR aims to provide consistent building blocks for modern .NET applications.

When contributing, please consider whether a change:

- Reduces boilerplate.
- Improves developer experience.
- Fits existing architectural patterns.
- Keeps the public API consistent.
- Avoids introducing unnecessary complexity.

Changes that conflict with these principles may not be accepted, even if technically correct.

## Documentation

Documentation improvements are always welcome.

Examples, tutorials, and clarifications are often just as valuable as code contributions.

## Code of Conduct

Please be respectful and constructive when interacting with other contributors.

Healthy technical discussion is encouraged.

## Licensing

By submitting a contribution, you agree that your contribution may be distributed under the project's license.
